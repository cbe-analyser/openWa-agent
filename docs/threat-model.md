# Threat model

This is a working threat model for OpenWa Agent 0.1.0. It is not the result of an external audit. Report weaknesses as described in [SECURITY.md](../SECURITY.md).

## Assets

| Asset                                                        | Where                               |
| ------------------------------------------------------------ | ----------------------------------- |
| Customer messages, phone numbers, profiles, tickets          | PostgreSQL                          |
| WhatsApp access tokens and app secrets                       | PostgreSQL, encrypted (AES-256-GCM) |
| AI provider keys, HTTP tool secrets, webhook signing secrets | PostgreSQL, encrypted               |
| `ENCRYPTION_KEY`, `DATABASE_URL`                             | Server environment (`.env`)         |
| User passwords                                               | PostgreSQL, scrypt hashes           |
| Sessions and API keys                                        | PostgreSQL, SHA-256 hashes only     |
| The business's WhatsApp number and reputation                | Meta                                |

## Trust boundaries

1. **Internet → app**: browsers, API clients and Meta's webhooks.
2. **Customer text → AI model**: customer messages are untrusted input to the model.
3. **AI model → tools and outbound messages**: model output is untrusted input to the system.
4. **App → external services**: AI providers, Meta Graph API, HTTP tools, outbound webhooks, URL imports.
5. **Organization ↔ organization** in multi-tenant installations.

## Threats and mitigations

| Threat                                                           | Mitigations                                                                                                                                                                                                                                                                                     | Residual risk                                                                                                                                                          |
| ---------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Forged WhatsApp webhooks                                         | `X-Hub-Signature-256` HMAC verified on the raw body with the channel's app secret (constant-time compare); verify-token handshake compared by hash; per-channel URLs; rate limit                                                                                                                | A leaked app secret allows forgery until rotated                                                                                                                       |
| Replayed or duplicated webhooks                                  | Unique WhatsApp message IDs; webhook events stored and processed once; status updates cannot move backwards                                                                                                                                                                                     | —                                                                                                                                                                      |
| Prompt injection by customers ("ignore your instructions…")      | System prompt treats customer text and knowledge as data; deterministic injection detector forces a draft; tools are scoped server-side to the current organization and customer; high-impact tools need human approval; instruction-leak canary in the system prompt is checked in every reply | Models can still be manipulated into unhelpful or off-brand text; Copilot/Supervised modes limit exposure                                                              |
| Indirect injection via knowledge documents or tool output        | Knowledge and tool results are passed as quoted data; only admins/agents can add knowledge; URL imports are explicit                                                                                                                                                                            | A malicious document added by a staff member can influence answers                                                                                                     |
| AI asks customers for passwords, PINs or OTPs (phishing pattern) | Output check blocks replies that request credentials and escalates; inbound secrets and card numbers are detected and the conversation escalated                                                                                                                                                | Pattern-based; unusual phrasings may pass                                                                                                                              |
| AI invents facts (prices, refunds, dates)                        | Business-fact intents require retrieved evidence or a successful tool call; unverified claims become drafts; insufficient evidence leads to "I don't have that information"                                                                                                                     | Paraphrased hallucinations in otherwise grounded answers                                                                                                               |
| AI claims an action happened that did not                        | Claims of created tickets, refunds, etc. without a matching successful tool call become drafts                                                                                                                                                                                                  | —                                                                                                                                                                      |
| Unauthorized access to the dashboard                             | scrypt password hashes; account lockout after 8 failures; per-IP and per-email login rate limits; httpOnly, SameSite=Lax session cookies (Secure on HTTPS); sessions revocable; other sessions revoked on password change                                                                       | No 2FA or SSO yet                                                                                                                                                      |
| CSRF                                                             | Cookie-authenticated writes require a same-origin `Origin` and the `x-openwa-csrf` header, which cross-site forms cannot set                                                                                                                                                                    | —                                                                                                                                                                      |
| XSS                                                              | React escaping; no `dangerouslySetInnerHTML` for user content; Content-Security-Policy with per-request nonce; `X-Frame-Options: DENY`; HSTS on HTTPS                                                                                                                                           | —                                                                                                                                                                      |
| Privilege escalation inside an organization                      | Role-based permissions checked on every route (owner, admin, agent, viewer); API key scopes limited to an allow-list that excludes account and security administration                                                                                                                          | —                                                                                                                                                                      |
| Cross-tenant data access                                         | Every query filtered by the caller's organization; tools bind organization and customer on the server; tests cover isolation for users, API keys and organization switching                                                                                                                     | A missed filter in future code; covered by review and tests                                                                                                            |
| Stolen API key                                                   | Keys hashed; scoped; optional expiry; revocation; rotation with grace period; last-used time shown                                                                                                                                                                                              | Valid until revoked                                                                                                                                                    |
| SSRF via URL imports, HTTP tools, webhooks                       | DNS resolution checked against private, loopback, link-local and metadata ranges, including after redirects; only http(s); size and time limits                                                                                                                                                 | Provider base URLs for OpenAI-compatible and Ollama providers may point to private hosts by design (self-hosted models); only users with `settings:write` can set them |
| Secret leakage                                                   | Secrets encrypted at rest; never returned by the API (only "set" flags or short hints); log redaction for keys, tokens, bearer headers and card-like numbers; error responses contain no stack traces; secret scanner in CI                                                                     | Secrets in process memory; database plus key compromise reveals everything                                                                                             |
| Leaked database backup                                           | Secrets in it are encrypted with `ENCRYPTION_KEY`, which is not in the database                                                                                                                                                                                                                 | Customer messages in the backup are plaintext; encrypt backups                                                                                                         |
| Abuse and cost exhaustion (message floods)                       | Webhook and API rate limits; bursts coalesced into one AI run; monthly token budgets per provider; spam intent ignored                                                                                                                                                                          | A determined attacker with many numbers can still consume budget up to the limits                                                                                      |
| Runaway automation (loops, spamming customers)                   | Max tool rounds and calls per run; follow-ups deduplicated and limited; 24-hour window and opt-out enforced in code; organization pause and global kill switch                                                                                                                                  | —                                                                                                                                                                      |
| Race between human takeover and AI send                          | Row lock and control version check before every AI send; queued AI messages superseded on takeover                                                                                                                                                                                              | —                                                                                                                                                                      |
| Dependency vulnerabilities                                       | Pinned versions; `npm audit` in CI; Dependabot                                                                                                                                                                                                                                                  | See `SECURITY.md` for known, assessed advisories                                                                                                                       |
| Loss of data                                                     | PostgreSQL backups ([operations.md](operations.md#backups)); durable job queue with retries and dead letters                                                                                                                                                                                    | Depends on the operator running backups                                                                                                                                |

## Operator responsibilities

- Keep `ENCRYPTION_KEY` and `.env` secret and backed up separately.
- Run behind HTTPS; keep the OS, Docker images and dependencies updated.
- Give team members the lowest role they need; remove leavers.
- Choose AI providers whose data handling meets your obligations ([data-protection.md](data-protection.md)).
- Review AI behaviour before enabling Autonomous mode.
